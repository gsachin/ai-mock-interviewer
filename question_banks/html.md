# HTML Question Bank

## Semantic HTML

Explain semantic HTML and why semantic elements are preferred over generic `div` elements. Expected points: meaning of elements such as `header`, `nav`, `main`, `section`, `article`, and `footer`, accessibility benefits, SEO implications, maintainability, and when a generic `div` is still appropriate.

## HTML document structure

Explain the standard structure of an HTML document. Expected points: `DOCTYPE`, `html`, `head`, `body`, metadata, character encoding, viewport configuration, document title, resource loading, and why correct document structure matters.

## Block vs inline elements

Compare block-level and inline HTML elements. Expected points: how elements participate in layout, examples of each, width and height behavior, line wrapping, how CSS changes display behavior, and why relying only on the default classification can be misleading.

## Forms and input types

Explain how HTML forms work and how to build a robust form. Expected points: `form`, `label`, `input`, `textarea`, `select`, `button`, appropriate input types, `name` attributes, browser validation, submission methods, and accessibility.

## HTML accessibility

How do you make an HTML page accessible? Expected points: semantic elements, heading hierarchy, labels, keyboard navigation, alternative text, accessible forms, focus management, ARIA usage when necessary, and avoiding inaccessible custom controls.

## ARIA attributes

Explain what ARIA is and when it should be used. Expected points: roles, states, properties, relationship with semantic HTML, why native HTML should be preferred, common attributes such as `aria-label` and `aria-expanded`, and avoiding unnecessary or incorrect ARIA.

## HTML5 media

Explain how HTML5 supports audio and video without third-party plugins. Expected points: `audio`, `video`, `source`, controls, fallback content, codecs, captions and tracks, accessibility, autoplay restrictions, and responsive media considerations.

## Images and responsive images

How do you efficiently serve images in modern HTML? Expected points: `img`, `alt`, intrinsic dimensions, `srcset`, `sizes`, `picture`, responsive image selection, lazy loading, image formats, and preventing layout shifts.

## HTML loading and performance

How does the browser load and process an HTML document? Expected points: parsing HTML, constructing the DOM, discovering resources, CSS and JavaScript interaction, render-blocking resources, `defer`, `async`, preload, and techniques for improving initial page performance.

## Forms validation

Compare native HTML validation with JavaScript-based validation. Expected points: attributes such as `required`, `pattern`, `min`, `max`, and input types, browser validation behavior, custom validation, server-side validation, security considerations, and why client-side validation cannot replace server-side validation.

## HTML links and navigation

Explain how hyperlinks work and how to build secure and accessible navigation. Expected points: `href`, absolute versus relative URLs, fragment links, navigation semantics, opening new tabs, `rel` attributes, keyboard accessibility, and avoiding links that behave like buttons.

## Tables

Explain how to create an accessible HTML table. Expected points: `table`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`, table captions, row and column headers, `scope`, when tables are appropriate, and why tables should not be used for page layout.

## DOM

What is the DOM and how does HTML become a DOM tree? Expected points: parsing HTML, nodes and elements, parent-child relationships, DOM APIs, differences between HTML source and live DOM, DOM manipulation, and how JavaScript interacts with the DOM.

## Web storage

Compare `localStorage`, `sessionStorage`, cookies, and server-side storage. Expected points: persistence, scope, capacity, request transmission, security implications, expiration, appropriate use cases, and why sensitive information should generally not be stored in client-side storage.

## HTML security considerations

What security issues should developers consider when generating and handling HTML? Expected points: cross-site scripting, unsafe HTML insertion, escaping and sanitization, untrusted user content, Content Security Policy, safe URL handling, and the importance of server-side security controls.
